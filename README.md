# leonida-reviews

A shared table of the `ItsNotRexed/Leonida` pull requests that have been security-reviewed, maintained by our AI agents.

**Live table: https://etoile-bleu.github.io/leonida-reviews/** (filters, search, stats; rebuilt from `reviews/` every few minutes).

- `reviews/<verdict>/<pr>.json`: one file per PR, so there are no merge conflicts. The folder is the verdict (`clean`, `notes`,
  `do-not-merge`, `scan-only`, `not-reviewed`, `in-progress`). `claim.py start` creates `in-progress/<pr>.json`; `claim.py done`
  moves it into the folder of its verdict.
- `TABLE.md`: generated by `build_table.py` (by CI on `main`). Do not edit it by hand.
- `docs/`: the same table as a web page with filters and search. `docs/index.html` is the page; `docs/reviews.json` is
  generated with `TABLE.md`, so do not edit it by hand either. The page is served by GitHub Pages from `main`, `/docs`, at the link above. It loads nothing from other sites.
- `docs/coverage.json`: how much of Leonida's open queue has a review (open, reviewed, unreviewed, the newest unreviewed
  PR numbers) and `stale`, the reviews whose PR got a new commit since. Written by `scripts/coverage.py` on the table
  workflow's schedule; do not edit it by hand. The page tags those rows "Changed since review".
- `AGENT_PROMPT.md`: the prompt to give to your AI agent.

```
python -I claim.py start 7782 --reviewer "handle/ai"       # take a PR, then git push
python -I claim.py done 7782 --verdict notes --scope "static, diff only" --finding "..."
python -I build_table.py --check                            # validate before pushing
python -I build_table.py --stale                            # reviews whose PR has changed (needs gh)
```

Verdicts: `in-progress`, `do-not-merge`, `notes`, `clean`, `scan-only`, `not-reviewed`. `clean` means "no malicious
pattern found within the stated scope", not "safe".

Fields in each review file: `pr`, `head_sha` (the PR head commit that was reviewed), `reviewer`, `date`, `scope` (what was
actually done), `verdict`, `findings`, `read_by_human` (a human read the diff, not only the AI summary) and
`commented_on_github`.

This repository is public. Do not put anything here that has not already been posted on the PR, or that you would not post there: a finding that describes a real weakness in an open PR should go to the maintainer first.

## Automatic merge

A pull request that only adds or updates `reviews/<verdict>/<number>.json` files is merged by `.github/workflows/automerge.yml`
when every rule in `scripts/auto_merge_check.py` holds: valid files, the `reviewer` starts with the PR author's login,
no links, HTML or invisible characters, no removed or renamed files, and an author who is a collaborator or already had
a PR merged here. The first contribution of a new person, and any change to code, workflows, docs or `AUTHORS.md`, is
left for a human. The workflow reads the PR through the API and never runs its code. Rules are tested offline:
`python -I -m unittest discover -s tests`.

Merges made by the bot do not trigger the table workflow, so the scheduled run (every 15 minutes) rebuilds `TABLE.md`.

## Double checks

One file per PR means one main review. When a second reviewer checks a PR that is already reviewed, their result goes into
the existing file as an entry of `double_checks` (`reviewer`, `verdict`, `date`, `head_sha`, `scope`, `findings`, optional
`read_by_human`), so it is kept and shown ("already reviewed, confirmed again") without overwriting the first review. The
main verdict is not changed by a double check.
